# Minecraft 版本协议维护

参考 `F:/Codexus/Codexus.Plugin.Base.*`，沿用已经迁入的 `V1206` 方式：包模型直接位于当前程序集的版本目录，使用 `PacketReader` / `PacketWriter`。不创建 Base 插件包，不引入 `Codexus.Development.SDK` 或另一套事件总线。

## 版本与范围

| 参考目录 | Minecraft | 协议号 | FandNEL 目录 | 模型范围 |
| --- | --- | ---: | --- | --- |
| Base.108X | 1.8.x | 47 | V108X | 动画、双向插件消息 |
| Base.1122 | 1.12.2 | 340 | V1122 | 聊天、插件消息、玩家位置与视角、加入游戏、区块 |
| Base.1200 | 1.20 / 1.20.1 | 763 | V1200 | 插件消息、加入游戏、玩家与实体移动、生成、传送、交互、挥手、物品使用、系统聊天 |
| Base.1206 | 1.20.5 / 1.20.6 | 766 | V1206 | 原有协议模型与 Heypixel 处理，不重复移植 |
| Base.1218 | 1.21.8 | 772 | V1218 | 配置阶段客户端信息/已知资源包/插件消息；游戏阶段移动、交互、生成、位置同步、队伍、元数据、系统聊天 |
| Base.12110 | 1.21.10 | 773 | V12110 | 同上，实体生成使用 LpVec3；独立的包 ID 和元数据表 |

参考项目中的四种玩家移动包合并为 `PlayerMovementPacket`，三种实体相对移动包合并为 `EntityMovePacket`，Configuration/Play 和双向插件消息共用各版本的 `CustomPayloadPacket`。文件数量不对应参考项目的 SDK 事件、工具类数量。

版本模型的 `Read` / `Write` 只处理载荷，不包含包 ID、帧长度、压缩或加密。模型通过 `RegisterPacketModelAttribute` 集中声明连接状态、方向、包 ID 和协议版本，由 `PacketRegistry` 反射扫描后自动注册为只读解析器；业务处理器可从 `PacketContext.TryGetParsedPacket<T>` 读取结果。解析失败只记录在当前上下文，原始载荷继续转发。各版本入口保留明确类型，字段完全相同的入口委托给已有模型，避免维护重复解析器。没有静态 `Read` 入口的辅助类型不会被扫描。

`Components` 集中处理 1.21.8/1.21.10 的 0–95 号物品组件边界，`Metadata` 集中处理两个版本的 serializer 表。版本参数必须来自握手确认的协议号，不能按最新版本猜测。物品组件值保留原始字节；需要业务修改时在已确认的字段边界替换。

## 版本差异与保留规则

- 1.20 的系统聊天内容为 JSON 字符串，1.20.6 及新版本为网络 NBT。
- 1.21.8/1.21.10 玩家移动保留完整 `Flags` 字节，`OnGround` 只解释最低位。
- 1.21.8 物品使用增加视角，方块交互增加 `WorldBorderHit`；不得复用 1.20.6 的旧载荷布局。
- 1.21.10 实体生成在坐标之后写 `LpVec3` 速度，再写角度和实体数据；1.21.8 使用尾部三个 Short 速度。
- 1.21.10 删除 CompoundTag 元数据 serializer，后续 ID 发生位移，并增加铜傀儡状态、氧化状态和 ResolvableProfile。
- 元数据中的未知 serializer、粒子及内联画作沿用参考实现的透传策略：`TryReadEntries` 返回 false 时使用原始 `MetadataData`，不能使用部分解析结果重写原包。
- 加入游戏、队伍及 1.12.2 区块的未解释尾部保留，不假定其字段布局。参考 1.12.2 区块写出时丢弃方块实体的问题没有照搬；已有尾部完整保留，无尾部时写出空列表。

## 已接入和预适配的区别

IRC 聊天使用版本包 ID 和聊天模型；Configuration 状态机使用集中包 ID。登录、压缩、加密及未注册包转发继续使用现有代理路径。自动解析是观察步骤，不替代需要副作用的业务处理器；后续处理器改写载荷后，`PacketContext` 会清除旧的解析结果，避免读取过期对象。

其余模型用于尚无具体服务器处理器的版本预适配。仅有模型不等于已经适配某个服务器的专有握手、反作弊协议或所有游戏状态处理；不自动启用 Codexus 的模拟世界、队伍过滤和 SDK 事件副作用。Heypixel 仍只对协议 766 启用，不能因增加版本目录就放宽这一限制。

游戏版本枚举包含 1.21.8/1.21.10；网易远端目录的 `McVersionId` 不等同于 Minecraft 协议号或本地枚举值，没有明确映射时不得编造。

## 修改与人工验证

先对照相应版本的只读参考源码和仓库 `minecraft-java-protocol-docs/versions` 快照，再修改包 ID 与布局。修改公共格式时检查所有委托调用的版本，避免仅修复一个入口。

按项目约定不增加或运行自动化测试。每次修改后执行后端 `dotnet build --no-restore`，并区分编译结果和真实服务器联调。人工回归应覆盖各版本登录、重新进入配置阶段、聊天、移动/旋转、实体生成/位置同步、双手交互、物品组件、队伍与元数据；1.20.6 另需回归末影珍珠和服务器传送。未有真实服务器条件的版本只能标记为预适配。
